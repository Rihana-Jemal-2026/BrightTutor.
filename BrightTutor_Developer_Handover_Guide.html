🏛️ 1. System Architecture & Tech Stack

BrightTutor is designed following Clean Architecture principles with strict separation of concerns, ensuring testability, maintainability, and loose coupling.

🖥️ Backend Architecture (.NET 8)
  • BrightTutor.Domain: Core domain entities (User, Student, Teacher, Course, ClassGroup, Attendance, Permission), value objects, and domain enums.
  • BrightTutor.Application: MediatR CQRS Commands & Queries, FluentValidation pipeline behaviors, Application DTOs, and Interfaces.
  • BrightTutor.Infrastructure: EF Core PostgreSQL DbContext, entity configurations, BCrypt password hashing, JWT Token generation, and automated seeding (DbInitializer).
  • BrightTutor.Api: RESTful controllers, global exception handling, Swagger documentation, and JWT bearer authentication.
🌐 Frontend Architecture (Angular 19)
  • Standalone Components: Modern Angular architecture with zero NgModules for faster lazy-loading and tree-shaking.
  • Reactivity & Signals: State management powered by Angular Signals (signal, computed) and reactive data fetching (rxResource).
  • Dynamic Searchable Selects: Reusable SearchableSelectComponent with instant typeahead search across thousands of entities (no raw GUID inputs).
  • Vanilla CSS Design System: Clean styling, glassmorphism, responsive data cards, status badges, and subtle micro-animations.

🔐 2. Role-Based Access Control & Permission Matrix

The system implements a hybrid Role-Based (RBAC) + Dynamic Permission System. Permissions are stored in the PostgreSQL database and can be dynamically customized per role by the Super Admin at runtime without code deployment.

Permission Code Module Description Admin Teacher Student Parent
users.view / manage Users Create, edit, deactivate, and assign user roles ✓ Full ✕ ✕ ✕
courses.view / manage Courses Manage courses, subjects, class groups & capacities ✓ Full ✕ ✕ ✕
attendance.mark Attendance Submit Group, Online, and Home Visit attendance ✓ All ✓ Own ✕ ✕
attendance.view Reports View attendance logs, calendars, and performance summaries ✓ All ✓ Class/Own ✓ Personal Only ✓ Child Only
settings.manage Settings Dynamic Permission Matrix & Admin System Actions ✓ Full ✕ ✕ ✕
🛡️ Critical Security & Privacy Invariants
  • Super Admin Immunity: The account admin@brighttutor.com can NEVER be deactivated and can only be edited by themselves.
  • Teacher ID Locking: In attendance marking forms and teacher reports, the Teacher ID is permanently locked to the logged-in teacher's ID. Teachers cannot submit attendance on behalf of other instructors.
  • Student Privacy Scoping: Students only see their own attendance records on the calendar, summary, and group attendance views. Other students' records in the class are filtered out.

🔌 5. REST API Endpoints & Entity Reference

HTTP Method Endpoint URI Authorization Functionality
POST /api/auth/login Anonymous Authenticates user and returns JWT Token & User Info
POST /api/auth/change-password [Authorize] Changes current authenticated user's password
GET / POST /api/users [Authorize(Roles="Admin,Teacher")] Lists active users / Registers new users (Admin only)
GET / POST /api/courses [Authorize] Retrieves course catalog / Creates courses
GET / POST /api/classgroups [Authorize] Retrieves class groups / Creates groups with capacity
POST /api/attendance/group [Authorize(Roles="Admin,Teacher")] Submits roster attendance using UPSERT strategy
GET /api/attendance/group [Authorize] Retrieves group attendance records for date
POST /api/attendance/online [Authorize(Roles="Admin,Teacher")] Records online session attendance
POST /api/attendance/home/check-in [Authorize(Roles="Admin,Teacher")] GPS Check-In for student home visit
POST /api/attendance/home/check-out [Authorize(Roles="Admin,Teacher")] GPS Check-Out for student home visit
GET /api/attendance/class-report [Authorize] Aggregate attendance metrics for class group
GET /api/attendance/teacher-report [Authorize] Conducted session statistics for teacher
GET /api/attendance/student-calendar [Authorize] Monthly calendar attendance days for student
GET /api/attendance/student-summary [Authorize] Aggregate performance rate for student
GET / POST /api/permissions/roles/{roleId} [Authorize] Fetches / Updates dynamic role permissions
GET /api/dashboard/summary [Authorize(Roles="Admin")] Executive dashboard system metrics
💡 How to Run the Solution Locally
  1. Backend: Navigate to backend/ and run dotnet run --project BrightTutor.Api (Starts on http://localhost:5198).
  2. Frontend: Navigate to frontend/brighttutor-client/ and run npm start or ng serve (Starts on http://localhost:4200).
  3. Database: PostgreSQL running at localhost:5432, database brighttutor. All migrations and seed data auto-apply on startup via DbInitializer.SeedAsync().
